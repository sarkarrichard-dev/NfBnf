<objective>
Tracer for Phase 3: the "Re-check now" path, end to end, on the real India journal shape.

POST /api/exit-recheck/run -> exit_recheck.run_recheck -> India journal (trades + feedback notes)
-> exit-reason classifier -> per-(lane, index) stats under today's stop distance -> confidence-ladder
verdict -> one learned_settings row -> GET /api/exit-recheck. Proven by tests on synthetic rows AND
by one read-only run against the real journal.

Purpose: EXIT-01 asks for a repeatable re-check of the stop distances against recent live-journal
data. Every number this needs already has an owner (ladder in strategy_learning, net-of-charges in
strategy_performance, exit reasons in day_review), so this plan is glue, not new maths. Later plans
expand from this proven slice: the India "what would another distance have done" replay (03-04),
crypto + commodities + drift warning + Telegram + daily run (03-05), dashboard panel (03-06).

Reality check, so nobody mistakes it for a bug: every segment will say "not enough data yet" today
(India buy 3/4/3 trades, sell 10/10/9 under today's distances, 2-5 trading days each). Verdict and
drift logic can only be proven on synthetic fixtures; the real first output is "not enough data yet"
with the real numbers still shown.

Plan-level decisions (orchestrator-settled, recorded here):
- Ladder thresholds: import strategy_learning._state / _frozen / OBSERVE_MAX / READY_MIN_DAYS /
  FREEZE_LOOKBACK; never copy the numbers. Effective bar = 40 trades and 15 trading days. D-03 says
  14 days; its stated intent is "the same bar used everywhere else", which is this ladder. No segment
  is near either bar today.
- Segment = (lane, index) for India, NOT the scorecard's (strategy_mode, index): the scorecard splits
  the buy lane by candlestick pattern, which would shred an already thin sample.
- Paper and live trades are pooled per segment (the stop rule is identical in both modes).
- The POST is non-financial and is NOT behind require_admin_secret: it cannot place an order or
  change a stop, it only recomputes from journals and writes its own row — same footing as
  POST /api/settings/features. The whole /api is behind DASHBOARD_PASSWORD when set.
- Baseline/drift fields (03-05) and the India replay (03-04) are added to the same row and module
  later; the row shape here is the stable contract the dashboard (03-06) reads.
