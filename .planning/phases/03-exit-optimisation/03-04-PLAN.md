<objective>
D-02 asks for a suggested better stop distance, in rupees and win-rate points, for Richard to approve.
For India this is possible from real recorded data (index ticks since 2026-08-29, real option-chain
quotes since 2026-09-23); for crypto and commodities no intra-trade price path is recorded anywhere,
so they get the honest "no replay data yet" (03-05).

This plan builds the India replay EARLY, right after the tracer, as a read-only feasibility step:
Task 1 builds and unit-tests the replay on a tmp market log; Task 2 runs it on the real data and
measures how often it reproduces the real exits at today's distance; Task 3 wires the suggestion gate
into the India verdict. If Task 2 shows poor reproduction, nothing changes in Task 3 — the gate then
returns replay_unreliable ("replay not reliable yet") for every segment, which is the accepted
fallback, not a failure: the shipped behaviour is stats + drift + that plain note, with
replay_diagnostic() kept for manual looks.

Today no India segment is ready, so the real daily run never reaches the replay yet; the gate is
proven on synthetic fixtures.

Plan-level decisions (recorded): match threshold 0.8 — four of every five real exits reproduced;
below that, the replay's rupee comparison measures the replay's own error as much as the stop.
Timing tolerance 120 s — the live stop is checked on every tick or at worst every 20 s, so a
correct replay lands well inside two minutes; tick-delivery lag days (7 min on 2026-09-16, 29 min on
2026-09-17) will honestly show up as mismatches. Quote age limit 300 s (chain is recorded about once
a minute). Comparison is replay-vs-replay on the same trades (current distance vs candidate), so the
replay's systematic pricing error cancels out. Buy-lane wider stops are labelled approximate
because the buy lane's regime-flip exits in the extra time cannot be replayed from ticks.
</objective>
