<objective>
Dhan's ORD-02: a position is correctly reconciled after a broker disconnection, with no stale
or duplicate entry left in the journal — plus D-09's Telegram alert on every reconciliation
problem, copying crypto's already-correct pattern.

Findings this plan acts on (verified 2026-09-30):
- build_order_book_index, build_trade_fill_index and build_position_index
  (dhan_orders.py:110-136, 919-932) swallow every error and return {} — the same value as
  "Dhan has nothing". During a disconnect, sync_open_live_trades (990-1052) therefore sees no
  trade-book fill for a real LIVE_TRADED leg; resolve_leg_broker_status's strict rule turns the
  cached placement reply into REJECTED and reject_live_trade erases the live position from the
  journal with P&L 0, or — past the 5-minute grace — verify_trade_against_positions fails and
  close_open_trade marks it "closed outside the system" while it is still open at Dhan. Either
  way the stop-loss sweep stops watching a real position.
- reconcile() (reconcile.py:95-134) catches a failed position read, but build_position_index
  never raises, so the except branch is dead: a disconnect reads as "every leg GHOST_JOURNAL",
  and with RECONCILE_AUTO_REPAIR on, _repair_ghosts closes every open live row.
- reconcile() returns early with "no open live trades" (lines 110-113), so a position Dhan holds
  with no journal row — exactly what a failed mid-spread entry leaves behind — is never
  reported unless some other live trade happens to be open.
- reconcile() and its caller scanner._run_reconcile only log (Research, Findings for D-09).

Plan 02-03 added the strict= switch (default off); this plan turns it on where a wrong
"empty" answer causes harm.
</objective>
