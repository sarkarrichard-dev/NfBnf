<objective>
Dhan's half of ORD-01, part 2: the literal "cancel issued while an order is still being
placed" on the India side.

Today (verified 2026-09-30): once execute_plan returns LIVE_PENDING (the order is still
working at Dhan after the confirm wait), every close path — the dashboard Close and Close-all
buttons, the 20-second stop sweep, the 15:10 square-off — hits
execution_safety.validate_live_exit_allowed and is refused with "need confirmed LIVE_TRADED"
(execution_safety.py:448-473). Nothing cancels the working order, so it can fill after the
system or Richard decided to be flat. And Close-all (server.py:1933-1942) reads open_trades()
without waiting for an in-flight execute_plan, so a trade being placed at that moment is not
in its list at all.

This plan adds settle_pending_entry — the India mirror of Delta's settle_entry (plan 02-01):
under the same per-instrument lock placement holds, ask Dhan (D-06), cancel whatever is still
working, ask again, and act only on what Dhan confirms. Close-all gets a barrier that waits for
any in-flight placement first — the mirror of plan 02-02's crypto Close-all fix.

Behaviour when live orders are not enabled (Paper mode or disarmed) is unchanged: a pending
live row stays BLOCKED as today, because every broker action on this path — including the
exit that follows a lost cancel race — sits behind the existing live gate.
</objective>

## Flagged Assumptions (edge probe: unresolved, surfaced not dropped)

- **ORD-01 (unclassified edge):** the success criterion "neither a duplicate nor an orphaned order" is read as: no second entry or exit order for one decision, and no order left on Dhan that the journal and Richard do not know about. A partly-filled spread cancelled mid-fill can leave one real leg on Dhan; that case is reported by alert (and by plan 02-05's reconcile) rather than auto-closed, following reconcile.py's own "repairing partial fills means guessing at intent" rule.
- **Disarmed while pending:** when live orders are not enabled, a pending live entry is not cancelled by this route (unchanged BLOCKED), because the path can end in an exit order and every broker order sits behind the existing live gate.
